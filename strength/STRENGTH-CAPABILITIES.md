# Strength contract research (sanitized)

The inspected Android workout model supports executable exercise/rest steps and repeat groups. Repetition end-condition ID 10 and no-target ID 1 were observed in authorized historical template reads. These observations do not prove every editor combination, server write or watch feature.

Keep category/exerciseName as a pair. Work-step end condition, primary target, repeat count, rest placement and load convention are distinct axes. Null weight is not bodyweight or zero. Numeric weight encoding and verbal/relative-load options need independent conversion-chain/readback verification before use. RPE/RIR/technique cues should not be invented as Garmin target enums.

Editor/model source references from the original local analysis include `sources/com.garmin.android.apps.connectmobile.workouts.presentation.stepedit.h.java`, `sources/com.garmin.android.apps.connectmobile.workouts.data.model.j0.java`, and selected `o62` editor classes. They are deliberately not distributed. Public exercise-catalog research used `https://connect.garmin.com/web-data/exercises/Exercises.json` and `exerciseToEquipments.json`; the catalogs themselves are not bundled. Never send account tokens to static-catalog hosts.

Personal workout names/IDs/contents, activity feedback, prescribed training sessions and raw account/template snapshots are omitted. Historical account-specific strength helper scripts depended on a local unpublished adapter and were not copied as broken standalone tools. No personalized strength session is published or executed here. Calendar attachment and watch delivery remain separate operations with separate consent/verification requirements.
